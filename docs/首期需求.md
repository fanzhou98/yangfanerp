# 豆制品工厂 ERP：本机试运行范围

依据：2026-10-18《评估企业是否适合搭建ERP》的讨论，以及本聊天确认的“先在这台电脑试运行”。以最后确认的业务事实为准。

## 已确认的业务规则

- 工厂生产豆腐、豆干、千张（豆皮）、素鸡、熏干等产品；两组磨浆系统通常独立，特殊情况下供浆串线。熏干由豆干继续加工。
- 库管约13点订货、约22点发货；记录订货数量和实际发货数量，不能相互覆盖。业务日期独立于实际录入时间，以支持跨零点批次。
- 工厂不逐筐称重入库。司机在客户处卸货称重，客户早晨卖货前再次称重；两次原始记录都保留，不能标为工厂出厂实称。
- 支持多筐合称、分批追加称重。净重为各称重批次毛重减该批筐数乘该批单筐皮重；皮重和单价随单保存快照。
- 两次差异由经验判断，不强设阈值，不自动接受客户复称。会计人工接受客户重量，或标记待协商，协商完成填写最终结算重量及原因。
- 会计算票，出纳对照原始依据复核。修改已结算但未收款的单据后，原复核失效，需要重新结算、复核。
- 已收款单据在试运行版锁定，避免变更破坏应收账。正式版再实现冲销与红字单据。
- 昌吉在工厂系统中按普通批发客户管理，不管理其内部经营。
- 豆皮、素鸡可按10公斤标准包记录，但标准包装重量属于标准量，需要抽查。豆腐、豆干按筐和实际重量分别记录。
- 依客户处重量和工厂库存还原的产量是估算，不能独立认定生产损耗或准确验证出品率。

## 本次交付 v0.1

本地网页与 SQLite 数据库；默认仅监听127.0.0.1，模拟库管、会计、出纳岗位。

1. 经营工作台：业务日期筛选、待处理事项、销售和应收指标。
2. 客户及产品档案：唯一客户编号、市场/线路、计量单位、价格及皮重规则。
3. 订货与送货：多产品订单、实发数量、跨日批次、两次称重的多批次明细。
4. 结算：人工接受复称、待协商、填写协商结果，保存价格与重量快照。
5. 复核：显示原始重量、差额、结算依据，出纳明确核对后确认。
6. 应收与收款：复核后入账，分次收款、余额校验、客户对账和 CSV 导出。
7. 操作记录：记录时间、模拟岗位、操作类型与变更前后内容；单据修订号避免旧页面覆盖新内容。
8. 数据备份：一致性数据库备份；试运行和演示标识。

所有初始客户、价格、皮重、重量、收款均为虚构演示数据。岗位切换用于验证流程，不是身份认证；本版本不开放局域网或外网，不用于正式记账。

## 后续阶段

- 原料：分豆种采购、领用、盘点，实际成本与库存流水。
- 生产：分线投豆、辅料领用、用浆标准缸数、串线、剩货、报损、退货和豆干转熏干。
- 成本：月度分线/分产品成本，费用实际归集和明确分摊规则；标注实测、标准量与估算。
- 正式部署：实名账号及岗位权限、多人共享、原始凭据附件、自动备份及恢复、收款冲销、期初余额、打印单据、真实 Excel 导入核对。

## 试用验收

用一笔虚构订单走完：库管订货与实发 → 分批司机称重 → 会计录客户复称 → 人工判断 → 结算 → 出纳对照依据复核 → 分次收款 → 余额归零。

再验证：待协商不能复核；复核后修改单据使复核失效；已收款单据不能覆盖修改；超额收款被拒绝；两个页面使用旧修订号不能覆盖；重启后记录仍存在。


## v0.2 作业方式修正

用户试用反馈：逐个选产品、逐单打开称重、同客户产品分散算票，操作量不适合集中作业。本版改为客户乘产品订货矩阵、全部展开称重表、按客户集中算票与复核。加入键盘导航、Excel数字区域粘贴、按线路/批次筛选、统一事务保存和未保存输入保留。原始单号、称重记录、修订冲突与账款约束继续保留。详见《总表操作说明》。


## 2026-10-27补充：跨月费用迟到与暂估

水、电、燃气等抄表日不固定，费用按实际覆盖天数分到月份；上次抄表日不计、本次抄表日计入。用户确认月底先登记暂估，实际账单到后补差并留痕；实际覆盖部分替换对应暂估，未覆盖部分保留。暂估不生成待付款，实际账单作为唯一应付来源，登记日、成本归属期和实付日分别记录。已冻结月份不自动改写。2026-10-27进一步确认：费用属性勾选不定期后，月结按对应项目日均补齐空档；本月无实际账单沿用最近实际账单日均。下次到单核对原补充区间，已结月份保持原额，差额计入本次登记月并留痕；应付按实际账单整笔金额，原补充不额外产生待付款。月结入口放页首，不设独立暂估登记区。
