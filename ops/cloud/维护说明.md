# 洋帆 ERP 云端部署与更新维护

版本以包内 `VERSION` 为准。首次上线采用全新空库，不迁移本机客户、产品、订单、账号或历史账款。本机项目和数据库完整保留。发布压缩包不包含数据库、密码、测试脚本、截图或历史日志。

## 服务器布局

- 程序：`/srv/yangfan-erp/releases/版本号`，`current` 链接指向当前版本。
- 数据库：`/var/lib/yangfan-erp/erp.db`，独立于程序目录。
- 备份：`/var/lib/yangfan-erp/backups`，每份 `.db` 与对应 `.manifest.json` 一起保管。
- 服务：`yangfan-erp.service`，一个 Waitress 进程、四线程，仅监听回环端口 8765。
- 入口：Nginx HTTPS，校验证书、Host 和 Origin，登录 Cookie 强制 Secure。
- 配置：`/etc/yangfan-erp.env`，仅记录站点地址和数据库路径，不写密码。
- 定时备份：`yangfan-erp-backup.timer` 每小时执行；同机备份不等于异地备份。

## 首次安装

将软件包与 SHA-256 文件上传到阿里云 Workbench 文件管理的 `/root`，核对校验值后，解压到新的目录。不要把整个本机项目目录上传。

```sh
sha256sum -c yangfan-erp-0.37.0.tar.gz.sha256
mkdir /root/yangfan-erp-0.37.0
tar -xzf yangfan-erp-0.37.0.tar.gz -C /root/yangfan-erp-0.37.0
cd /root/yangfan-erp-0.37.0
bash ops/install_cloud.sh 你的公网IP或域名
```

安装脚本先安装服务和空数据库，HTTP 入口只处理证书校验，业务访问返回维护状态。请由管理员本人在服务器终端交互输入账号、姓名和密码，密码不发送到聊天、不写进命令。

```sh
sudo -u yangfan-erp python3 /srv/yangfan-erp/current/server.py --database /var/lib/yangfan-erp/erp.db --create-admin
```

HTTPS 证书取得后执行 `bash /srv/yangfan-erp/current/ops/cloud/enable_https.sh`。公网 IP 证书可使用支持该功能的 Certbot 5.4 或更高版本及 Let's Encrypt 的 shortlived 配置；必须自动续期并测试续期。安装脚本不自动接受证书服务条款，不生成自签名公网证书。无可信证书时不得通过 HTTP 登录。

安全组只开放所需的 80（证书验证与跳转）、443（HTTPS）；不开放 8765 或数据库端口。SSH 管理入口和 Workbench 登录按阿里云实际连接方式保留，避免误锁自己。首次启用公网入口前需核对访问范围。

## 上线后如何一起更新

你在本聊天描述要修改的页面、业务规则和具体例子；尽量说明原来是什么、希望变成什么。截图遮住密码即可。通常不需要把完整业务数据库发送给我。

我在本机项目中修改，使用临时数据库完成业务、权限和浏览器测试，更新 VERSION 并生成新的发布包；你确认变更内容后，安排不影响录单的维护时间，工作人员保存并退出。随后可以继续授权我使用 Safari 中已登录的 Workbench 上传和更新。

每次升级从“新的解压目录”执行：

```sh
sudo bash ops/upgrade_cloud.sh
```

脚本会校验包、安装新版本依赖，开启维护入口、停止写入，生成升级前一致性备份，在候选副本迁移并核对完整性和业务勾稽，再切换程序及候选数据库。只有健康检查通过才恢复入口。升级失败会保持维护状态，需要检查原因；不得反复运行脚本、清空数据库或直接修改财务状态。

升级成功后脚本会做例行清理：只保留当前版本和上一版本程序，候选数据库保留最近两份，备份保留最近两周（并始终保留最新一份），同时清除 /root 旧解压目录、pip 缓存和各版本 __pycache__。清理只删除可重建或已有备份的文件，不动运行库和备份清单。

从 v0.43.0 起，全部结构和历史迁移经统一目录登记，重复升级不再重跑已完成步骤。可用 `python3 ops/migrate.py plan --database /var/lib/yangfan-erp/erp.db` 只读查看计划。云端请求进程拒绝未完成升级或与当前程序不相容的数据库，不自行修补。部署初始化入口保留明确执行旧包价转公斤价的原有行为；普通本机启动及 `ops/migrate.py apply` 不做该转换，需指定 `--kilograms`。

升级后我会核对版本、健康、HTTPS、账号及关键业务；你抽查最近订单、库存、应收和采购记录，员工刷新浏览器后继续。无业务写入的例行检查无需创建假订单。

## 日常检查和故障反馈

```sh
sudo bash /srv/yangfan-erp/current/ops/cloud_status.sh
sudo journalctl -u yangfan-erp --since '30 minutes ago' --no-pager
sudo systemctl status yangfan-erp-backup.timer yangfan-erp-backup.service --no-pager
```

告诉我故障发生时间、使用账号的岗位、页面和点击步骤，以及有没有保存成功提示。可以提供上述状态输出；日志可能包含内部路径，发送前不要夹带账号密码或完整业务数据。不要先清缓存或重复登记收付款来试错。

服务会开机自启、异常退出后重启；这不等于故障已修复。我不会在聊天结束后持续监控。需要后台通知时，另行配置阿里云监控通知和备份失败告警，并明确通知对象。

## 备份与恢复

每小时本机一致性备份之外，每天将至少一份备份及清单通过 Workbench 下载到独立设备，私密保存；以后可增加经过授权的私有 OSS 异地备份。当前脚本不自动删除旧备份，需定期检查磁盘并在确认异机可恢复后制定保留策略。

恢复演练不会覆盖运行库：

```sh
sudo -u yangfan-erp python3 /srv/yangfan-erp/current/ops/erp_ops.py restore-drill --backup /var/lib/yangfan-erp/backups/实际备份.db
```

故障回退需同时考虑程序与数据库结构。先保持维护入口、停止服务、保留当前库，再按 `erp_ops.py prepare-restore` 和 `finalize-recovery` 生成并检查新的恢复候选，核对账号启停状态及恢复点之后的业务，随后切换相容的旧程序和候选库。不要把老数据库直接覆盖到运行中服务，也不要在员工重新录单后自动回退数据库。恢复后会注销旧会话、更换业务轮次，员工重新登录并补核恢复点之后的记录。

## 测试验收

本机发布前运行 `python3 ops/verify.py`。云端适配单元测试在 `tests/test_cloud.py`，真实 Waitress HTTP 测试需要安装 `requirements-cloud.txt` 后运行 `tests/test_waitress_cloud.py`。浏览器回归另行执行；测试仅连接临时库，不使用本机或云端业务库。

配置中的内存上限为应用 768MB，给 2GB 主机上的操作系统与 Nginx 留出空间。实际用户数和历史数据规模增长后，依据响应时间、内存及数据库写入冲突调整，不能把这个配置当作并发量保证。
