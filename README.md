# 昌吉市洋帆豆制品厂 ERP · v1.11.2

豆制品厂「订货 → 收款」的经营系统。同一套代码既跑本机（`server.py`，只监听 `127.0.0.1`），也跑云端（`cloud_app.py` WSGI + Waitress + Nginx HTTPS）。Python 标准库 + SQLite + 原生 JavaScript，无第三方 Python 依赖。

## 业务主线

订货 → 库存分配与装车实发 → 司机配送与两次称重 → 会计算票 → 出纳复核 → 应收与收款。配套：退货扣款、厂内转加工、日终结转、月结冻结、采购订单/验收/应付、原辅料与包装库存、期间成本分摊、豆渣收入、人事考勤工资、经营看板与报表地图。

- 金额按分保存；数量按产品发货单位（公斤/筐/包等）保存；业务日期独立于录入时间。
- 岗位：管理员、库管、会计、出纳、厂长、物流负责人、司机、老板。管理员按岗位配置查看/操作权限，服务端校验，请求头不能提权。
- 库管只经手数量与实物，不给价格与库存成本；会计负责计价，出纳负责复核与实际收付。

## 本机启动

```sh
python3 server.py --create-admin      # 首次交互建管理员，密码隐藏输入
python3 server.py --no-browser        # http://127.0.0.1:8765/
```

默认库 `data/erp.db`，可用 `--database /绝对路径/erp.db` 指定；所有维护工具必须使用同一路径。一个库只跑一个服务进程。`启动ERP.command` 可启动已有服务。

## 配送闭环日常操作

| 顺序 | 经办岗位 | 操作与结果 |
|---|---|---|
| 1 | 会计 / 物流 | 物流管理 → 配送服务商：新增或修改服务商档案；会计按客户地区维护每趟运费与生效日期，地区从客户档案列表选择。 |
| 2 | 库管 / 物流 | 配送排车：每趟选择车辆、司机档案、配送服务商，分配市场并保存。司机不需要开通登录账号；车辆司机档案在排班最后。 |
| 3 | 库管 | 保存库存与拟实发后，进入“配送明细与实发确认”，核对后点“确认实发”；保存草稿不等于确认实发。 |
| 4 | 库管 | 确认实发即生成配送明细与运费记录，不再确认实际出车或配送完成。改派已结算趟次前须先撤销未付款结算。 |
| 5 | 会计 | 财务管理 → 配送费结算：补齐跨地区或缺失报价的本趟运费，核对未关联实发提示，按服务商生成月度结算单，同时形成费用应付。 |
| 6 | 出纳 | 费用核销与付款：核对原始凭据，通过后登记实际付款，支持分次支付，未付余额随付款减少。 |
| 更正 | 会计 / 物流 | 未付款结算可在期间开放时撤销，原单与旧应付保留作废记录，更正趟次后重新生成；已付款记录或已结账期间不直接撤销。 |

配送费结算页可跳转并准确定位原费用。实发确认时的运费快照、改派及更正依据、结算单、应付和付款分别留痕。历史未记录的实发量不补零，不妨碍来源未变化的正常收款。

## 补偿款与混包扣皮

- 员工工资 → 社保补偿款统一设置：按生效月份维护基数及双方比例，勾选批量跟随人员；个人例外在员工工资标准中设置或恢复跟随，旧档案先保留原值。已确认、发放或结账月份不追溯。
- 会计算票 → 包法与组合皮重：维护任意包法与产品/物理框型组合标准，可另列客户专用标准。组合总皮重包含框子及包材，单位为公斤/个。
- 本单“包法 / 扣皮”中登记特殊包法数量，默认包法补足其余数量；应用后仍须保存单据。回框与欠框继续按物理框型计算。修改标准不重算旧单；旧“布框”保留原记录，不自动归类颜色。
