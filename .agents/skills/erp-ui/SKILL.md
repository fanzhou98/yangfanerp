# 洋帆 ERP 界面硬约束

适用项目 `/Users/zhoufan/Desktop/ERP系统`。目标是经办人看得懂、连续录入快、数据核得上。先读项目 AGENTS.md 和当前页面实现。本技能限定生产 ERP；它覆盖通用 frontend-design 对视觉冒险、字体实验、首屏装饰的建议。用户明确要求优先；仅安装技能不等于授权重做页面或扩大试运行范围。

## 导航与信息结构

- 复用 `erp_access.py` 的模块目录、已有分组/顺序与前端导航。保持岗位可见性、权限门、历史入口、返回路径；不得为“简化”移动模块、合并业务步骤或绕过权限。
- 维持左侧模块导航、顶部位置提示、正文筛选/表格/操作区。沿用现有SVG图标，不新造emoji导航或巨幅标题。
- 保存、确认算票、复核、付款分别保留原语义和数据绑定。不能把保存草稿写成业务已确认，也不能把试算写成已入应收。
- 必填输入和当前核对依据直接可见；仅次要补充内容可折叠，不把必须填写的框型或皮重藏进嵌套卡片。
- 普通文字与文字操作必须可辨认：普通正文不加下划线；文字按钮/链接使用现有深绿色、常显下划线，并具备悬停底色和可见键盘焦点。禁用时取消下划线并呈现禁用状态；不能仅靠相近颜色或鼠标移入才显示的效果区分可点击内容。实心业务按钮保持原按钮形态。
- 折叠面板与提示条统一：可折叠区域用通用折叠表头（左侧 4px 着色条、700/13px 标题、悬停变色、焦点框、「展开/收起」胶囊），展开态胶囊为实心主色；表示异常或待办需注意的折叠提示用暖琥珀配色（文字 #6f4300、左条 #c98518），与中性折叠条一眼可区分。新增页面直接复用 style.css 的通用 details 规则，不另写局部折叠样式。

## 表格和数字输入

- 常规表头/单元格居中；长备注、说明左对齐；已有明确会计数字列的右对齐可保留。不要把整表改成左对齐。
- 产品、实发、称重、皮重、回框、计价、金额沿用已验收的独立列。未经用户认可，不为凑固定列数合并字段、拆成卡片或改变顺序。
- 使用自动表格布局与列的合理最小宽度。空间不足时只让表格容器横向滚动；页面本身不能横溢出。禁止为了“1440宽不滚动”把中文压成逐字竖排。
- 数字使用系统字体和等宽数字特性。保留业务精度、空值/零、单位、正负号、禁用/只读与未保存标记；不要为视觉整齐改计算或四舍五入规则。
- 当前算票输入宽度基准：实发50px、框数52px、单价64px、重量/结算量88px；如真实值被裁切就加宽，不反向缩小字号。检验至少0、22、120、440、104.4、1069.20及该字段允许的较长小数。不要让number输入的步进按钮遮住数值。
- 表头用主名＋下一行单位，不重复堆解释；关键信息不能只靠悬停。异常短提示靠近对应字段，完整依据可在详情查看。

## 密度、字体、点击尺寸

| 项目 | 约束 |
|---|---|
| 正文/表格数字 | 13–14px；主数字不得低于13px |
| 单位/辅助说明 | 11–12px，不用浅灰小字承载必填或金额 |
| 标题 | 页面20–24px，分区14–16px；不加装饰性英文副标题 |
| 间距 | 以4px为步进，字段间8–12px，分区间12–16px，区域内边距12–20px |
| 单元格 | 垂直6–8px、水平4–8px；多框型可自然增高，不固定高度截断内容 |
| 桌面输入/按钮 | 可操作高度至少32px；小图标可点区域至少32×32px |
| 移动端 | 可点区域至少44×44px；可通过外层标签扩展命中区域，不强行放大整表 |
| 焦点/错误 | 保留键盘焦点框、Tab/Enter、输入校验及未保存状态；不能只用颜色区分错误 |

不以强行降低行高掩盖溢出，不以巨幅空白拉开操作距离。单行数字与同一列基线对齐。

## 色彩令牌（复用现有变量）

| 变量 | 值 | 用途 |
|---|---|---|
| --ink | #203a36 | 正文、核心数字 |
| --muted | #7c8b86 | 非关键辅助文字 |
| --green / --green-dark | #216c55 / #174e3f | 现有主操作、选中和悬停 |
| --line | #e6ece7 | 细边框与分隔 |
| --bg / --white | #f5f7f4 / #ffffff | 页面底色与工作区 |
| --soft | #eaf3ed | 轻量选中背景 |
| --orange / --red | #af7433 / #b34f44 | 待核对与错误 |

不修改全局调色板，不新增渐变、玻璃效果、大阴影、霓虹色或外部字体。现有蓝色未保存/下一步、紫色已保存专属规则等业务标记保留，不强行改成绿色。辅助文字颜色不用于金额、警告或必填标签。

## 明确反例

- 错：把“框型/扣皮”压成四行，再给每个产品放两张大“展开”卡片。对：保留独立列，框型名与窄数字框同行。
- 错：15列硬塞成9列，隐藏回框、单位和结算依据，声称无需横向滚动。对：保留业务信息；不足的宽度由表格容器滚动承担。
- 错：为了行宽把字体降到10px，或把440、104.4、1069.20裁掉一部分。对：先收空白，再按实际数据加宽对应输入。
- 错：把每个输入包装成营销卡片，加渐变、动效、大标题。对：白底紧凑工作表，沿用现有导航和令牌。
- 错：只有全页面远景截图、空表或DOM断言，就宣称设计验收通过。对：检查有真实结构的样例，并查看局部截图及实际输入值。

## 必须执行的截图自查

1. 修改前保留同页面基线。使用隔离合成库，不改正式库/账号，不读取私有凭证；无需业务写入时只读查看。
2. 页面修改后优先用已连接的 Playwright MCP，复用系统Chrome，隔离会话，单浏览器执行。MCP尚未接入本轮时可用现有Playwright脚本验证，并明确说明使用了脚本，不能冒称MCP已连接。
3. 用同一份包含真实结构的数据截图：普通/混框、缺少复称、长名称、较大数和小数、已保存/未保存/报错/只读。按变更选必要场景，不扫所有历史脚本。
4. 检查1440、390、320宽度；涉及紧密表格时另在用户实际桌面宽度看一次。先关闭无关浮层，恢复合适滚动位置，防止sticky表头在全页截图中造成错觉。
5. 同时取页面全景和受影响表格/行/输入框的局部截图。无整页横溢出；可见字段的实际值完整；表头不竖排；保存/确认按钮不遮行；展开后仍可操作。
6. **必须用图像查看工具逐张打开截图。** Screenshot保存成功、浏览器无异常、测试通过，均不等于视觉验收通过。发现不合格就修复后重截受影响场景。
7. 验证录入→计算→保存→刷新、计价切换、权限和未保存内容保护中受影响的步骤。不能在合成前端数据上只验369就宣称后端保存已验收。
8. 所有截图/日志放 `/tmp/erp-ui-*`，不要落在docs或发布目录。完成后关闭测试浏览器、会话和临时服务；不要结束用户原有ERP服务。
9. 发布前先给用户可查看的同数据前后局部图，说明具体改变。只有获得当前任务授权且必要验证通过才发布；试运行冻结、维护窗口和权限遵循AGENTS.md。不要新增不必要的审批流程。

全量与浏览器不并行，验证并发最多两路。MCP不可用时保留明确的未验收项，不以截图缺失换取“完成”。

## 左侧导航与全局折叠按钮

- 选中子模块时，父级分组只做「路径」提示：3px 浅色左竖条 + 加粗深绿文字，不加底、不描边；浅绿实底 + 深绿竖条只给当前子项。分组折叠箭头统一纯图标，当前组箭头用主绿色。
- 「全部收起 / 全部打开」必须是侧栏底部整宽次要按钮（≥40px、描边、悬停加深、可见焦点框，移动端 44px），不要做成 12px 侧边竖条或悬停才显示文字。
- 表格正文默认 13px；算票 worksheet、expanded-table 等窄表保留 12px 密度。辅助说明（页脚状态、分页、范围说明、侧栏版本与角标）下限 11px。
